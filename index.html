01A Different Way to Write the Same Problem

Soft Margin SVM's optimization problem can be rewritten in an entirely different, mathematically equivalent form: the dual.

The primal form, from the linear SVM:

min(w,b,ζ)  ½‖w‖² + C·Σᵢζᵢ    subject to   yᵢ(wᵀxᵢ + b) ≥ 1 − ζᵢ, ζᵢ ≥ 0

The dual form — the full derivation involves Lagrangian duality, a topic of its own, but the form itself is worth knowing for what it makes possible:

max(α)  Σᵢαᵢ − ½ΣᵢΣⱼ αᵢαⱼyᵢyⱼ(xᵢ·xⱼ)    subject to   0 ≤ αᵢ ≤ C,   Σᵢαᵢyᵢ = 0

Each training point i gets its own multiplier αᵢ, found by solving this instead of solving for w and b directly. With the optimal αᵢ's, prediction for a new point x becomes:

f(x) = sign( Σᵢ αᵢyᵢ(xᵢ·x) + b )

02What the Alpha Values Actually Mean

The dual form reveals something the primal form hides: each point's αᵢ tells you exactly how much it matters to the final boundary.

αᵢ = 0  for non-support vectors     αᵢ > 0  for support vectors

In the prediction formula above, a point with αᵢ = 0 contributes nothing to the sum — it could be deleted from the training set entirely and the boundary wouldn't shift by a fraction. Only points with αᵢ > 0, the support vectors, genuinely shape the decision. This matches the hinge-loss intuition from Part 1: a point comfortably and correctly classified beyond the margin has zero hinge loss, and correspondingly αᵢ = 0. A support vector — on, inside, or across the margin — has nonzero loss and αᵢ > 0.

03Why the Dual Form Matters: The Kernel Trick

In the dual objective and the prediction formula, the data xᵢ never appears alone — only ever inside a dot product, xᵢ·xⱼ or xᵢ·x.

That's the key. What if, instead of the dot product of the original features, we computed the dot product of some transformed, higher-dimensional version of those features, φ(xᵢ)·φ(xⱼ), without ever actually constructing φ(x)?

A kernel function K(xᵢ, xⱼ) does exactly this: it computes what φ(xᵢ)·φ(xⱼ) would equal, directly from the original xᵢ and xⱼ, without ever materializing φ(x). Wherever the dual form used xᵢ·xⱼ, substitute K(xᵢ, xⱼ) instead. This is the kernel trick, and it only works because of the dual form's dot-product structure — the primal form has no equivalent way to slot this in.

The dual form, by itself, is still just a different way of writing the same linear boundary — it computes xᵢ·xⱼ, an ordinary dot product. It's specifically replacing that dot product with a non-linear kernel function that lets the boundary bend.

Why: Statement 1 describes what a kernel corresponds to mathematically: a valid kernel is equivalent to an inner product in some higher- (sometimes infinite-) dimensional space, but that mapping is never actually constructed. Statement 2 is true read broadly: a kernel is a generalized similarity function. Polynomial measures similarity via a dot product; RBF measures it via distance instead — no notion of angle at all. Both are legitimately similarity functions; they just measure differently.

04The Polynomial Kernel: High Dimensions, No Extra Cost

For two 2-dimensional vectors x = (x₁, x₂) and z = (z₁, z₂), define the kernel:

K(x, z) = (x·z + 1)²

Expanded algebraically:

K(x,z) = 1 + 2x₁z₁ + 2x₂z₂ + x₁²z₁² + x₂²z₂² + 2x₁x₂z₁z₂

This is exactly the dot product φ(x)·φ(z), for the explicit 6-dimensional mapping:

φ(x) = (1, √2·x₁, √2·x₂, x₁², x₂², √2·x₁x₂)

We started with 2-dimensional vectors and got the exact result of a 6-dimensional dot product, without ever constructing those 6 features — just one squared dot product in the original 2D space.

05The RBF Kernel

The Radial Basis Function (RBF) kernel, also called the Gaussian kernel, measures similarity based purely on distance.

K(x, z) = exp( −‖x − z‖² / (2σ²) )

When x and z are identical, K = 1 (maximum similarity). As they move apart, K decays smoothly toward 0. Unlike the Polynomial kernel's explicit, finite feature expansion, RBF corresponds to an infinite-dimensional feature space — exactly why it can bend a decision boundary into extremely flexible shapes. σ controls how quickly similarity decays with distance.

Interactive · RBF Similarity Decay by σ

A smaller σ produces a narrower, thinner curve — similarity drops off sharply even with a little distance, so each point's zone of influence is small. A larger σ produces a wider, gentler curve, letting influence stretch further.

If σ decreases, what happens to the RBF curve?
  • The curve gets thinner
  • The curve gets thicker
  • No change
Why: A smaller σ shrinks the denominator 2σ². Dividing the same negative numerator −‖x−z‖² by a smaller denominator produces a larger-magnitude, more negative exponent at any given distance. exp(·) of a more negative number is smaller, so similarity falls toward zero faster. That's a narrower, thinner curve.
A quick note on notation

scikit-learn's SVC(kernel='rbf') exposes this same idea through gamma, where γ = 1/(2σ²). A small σ corresponds to a large gamma — watch the direction when tuning: high gamma behaves like the thin, sharply-decaying curve above.

06RBF vs. kNN: Similar Idea, Different Speed

RBF's whole premise — similarity based on distance to nearby points — sounds a lot like kNN's core idea. Does that mean they run at similar speeds?

Predict before you run

kNN's prediction cost grows with the entire stored training set, every time. Given what Section 02 established about support vectors, does RBF-kernel SVM's prediction depend on the entire training set too, or something smaller?

Why They Diverge · Prediction Cost

kNN compares a new point against every single stored training point, every time: O(n·d) per query. SVM's prediction formula only sums over points with αᵢ > 0 — the support vectors — typically a small fraction of the full training set. Same underlying "similarity to nearby points" flavour, genuinely different computational cost, because of what each algorithm keeps around after training.

An honest result, not a tidy one

A large, unexplained gap between kernels is a prompt to dig further — learning curves, a log-scale sweep of gamma, checking whether sparse-then-scaled features behave oddly under a distance-based kernel — not a result to narrate around with an unverified claim like "the data must already be near-linear." The honest position here is: we have a specific, checked F1 comparison, and a direction for further investigation, not a settled explanation.

A few good-to-know things, briefly

  • SVM's time complexity roughly scales with the number of support vectors at prediction time; training itself (solving the dual optimization) is typically O(n²) to O(n³) depending on the solver — part of why SVM tends to struggle to scale to very large datasets compared to, say, Logistic Regression.
  • SVM isn't only for classification. Support Vector Regression (SVR) adapts the same margin-based idea to predict continuous values instead.

09Recap

Dual formulation

Rewrites SVM's optimization in terms of Lagrange multipliers αᵢ, one per training point, instead of w and b directly.

Alpha and support vectors

αᵢ = 0 for non-support vectors, αᵢ > 0 for support vectors; only support vectors influence the final boundary.

The kernel trick

The dual form's dot-product structure enables replacing xᵢ·xⱼ with K(xᵢ,xⱼ), getting the effect of a much higher-dimensional space without constructing it.

Polynomial kernel

A single 2D computation matched an explicit 6D dot product exactly.

RBF kernel

Measures similarity by distance, decaying smoothly; σ (or gamma) controls how narrow or wide that decay is.

RBF vs. kNN

Both lean on distance-based similarity, but don't run at the same speed: kNN compares against every stored point; SVM sums only over its (typically much smaller) support vectors.

Kernels aren't automatic wins

On real, already near-linearly-separable data like word counts, a fancier kernel doesn't always beat a simple linear one — and knowing that is itself a useful result.
